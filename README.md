# BTC/RUB Radar

Android-приложение: опрашивает обменники, строит два списка — **купить BTC за рубли** и **продать BTC за рубли** — и сортирует их так, чтобы самое выгодное было сверху. Умеет ходить через Tor и опрашивать `.onion`-зеркала.

---

## Как получить APK

Android SDK локально не нужен — собирает GitHub.

1. Создай репозиторий на GitHub (можно приватный).
2. Залей туда содержимое этой папки:
   ```bash
   cd btcrub-radar
   git init && git add -A
   git commit -m "BTC/RUB Radar"
   git branch -M main
   git remote add origin git@github.com:ТВОЙ_ЛОГИН/btcrub-radar.git
   git push -u origin main
   ```
3. Вкладка **Actions** → сборка стартует сама (~4–6 минут).
4. Внизу страницы сборки, в разделе **Artifacts**, лежат `btcrub-radar-debug` и `btcrub-radar-release`. Качай, распаковывай, ставь APK.

Release подписан debug-ключом, чтобы APK ставился сразу. Для публикации замени `signingConfig` в `app/build.gradle.kts` на свой keystore.

### Если хочешь собирать локально

Нужен Android SDK (Android Studio или `cmdline-tools`), потом:
```bash
export ANDROID_HOME=~/Android/Sdk
gradle assembleDebug
```
APK появится в `app/build/outputs/apk/debug/`.

## Как подключить свои сайты

**Парсеры не зашиты в код.** Источники задаются конфигом прямо в приложении: кнопка **⚙ (Источники)** → **Добавить**. Новый сайт не требует пересборки APK.

Три типа источников:

| Тип | Когда использовать |
|---|---|
| `JSON` | у сайта есть API. Самый надёжный вариант — бери его, если он есть |
| `HTML` | API нет, парсим страницу CSS-селекторами. Ломается при редизайне сайта |
| `BESTCHANGE` | встроенный адаптер под публичную выгрузку BestChange |

### JSON-источник

Указываешь пути точечной нотацией, индексы поддерживаются: `data.rates[0].ask`.

- `buy_path` — цена, по которой **ты покупаешь** BTC (обменник продаёт)
- `sell_path` — цена, по которой **ты продаёшь** BTC (обменник покупает)
- `min_in_path` / `max_in_path` — лимиты в валюте, которую ты **отдаёшь**
- `reserve_path` — резерв в валюте, которую ты **получаешь**

Если курс отдаётся как «BTC за рубль» — поставь галочку «Курс перевёрнут». Если в копейках — множитель `0.01`.

### HTML-источник

`row_selector` указывает на строку таблицы, остальные селекторы — внутри строки. Например:
```
row_selector:   table.rates tbody tr
name_selector:  td.exchanger
buy_selector:   td.give
sell_selector:  td.get
```

### Кнопка «Тест»

В редакторе источника есть **Тест** — дёргает сайт прямо сейчас и показывает, сколько предложений распарсилось и первые три курса. Пользуйся ей, пока цифры не сойдутся с тем, что видно на сайте глазами. Это быстрее, чем гадать.

### Перенос конфига

Иконки ⬆/⬇ в шапке — экспорт и импорт всего набора источников в JSON. Удобно перекидывать между устройствами.

## Tor и .onion

Приложение **не тащит с собой Tor-бинарник** — оно ходит через прокси [Orbot](https://orbot.app/).

1. Поставь Orbot (F-Droid, Google Play или orbot.app), запусти его.
2. В приложении: чип **TOR** в шапке → режим **Orbot HTTP**.
3. Жми **Проверить Tor** — приложение сходит на `check.torproject.org` и подтвердит, что трафик реально идёт через сеть.
4. В источнике заполни **Onion URL**. Когда Tor включён, приложение пойдёт именно туда.

### Почему HTTP-прокси, а не SOCKS

Неочевидный, но важный момент. OkHttp с `Proxy.Type.SOCKS` резолвит имя хоста **до** создания сокета и отдаёт прокси готовый IP. Для `.onion` это смертельно: такого адреса нет в обычном DNS, резолв падает, запрос не уходит вообще. Плюс в clearnet это утечка DNS мимо Tor.

С `Proxy.Type.HTTP` OkHttp шлёт прокси `CONNECT hostname:port`, то есть **имя**, а резолвом занимается сам Tor. Поэтому `.onion` работает через HTTP-порт Orbot (8118), а не через SOCKS (9050). Режим SOCKS в настройках оставлен для clearnet-трафика, где это не принципиально.

## Алерты и голосовой ассистент

Иконка 🔔 в шапке — раздел алертов.

- **Алерт** = направление + условие + порог + (необязательно) фильтр по обменнику. Например: «продажа BTC где угодно дороже 9 700 000 ₽» или «покупка у `Alpha` дешевле 9 400 000 ₽». Порог сравнивается с **эффективным курсом** (с учётом комиссии), а не с витринным.
- **Фоновый мониторинг** проверяет курсы, даже когда приложение закрыто, и шлёт уведомление при срабатывании. Честная оговорка: Android не даёт периодической задаче частить — минимум 15 минут, а в спящем режиме может и реже. Для посекундного слежения нужен постоянный foreground-сервис (жрёт батарею) — отдельное решение, если захочешь.
- **Ассистент** проговаривает срабатывания голосом. Имя настраивается, голос — мужской/женский (насколько позволяет TTS-движок прошивки). Работает офлайн, если в системе стоит офлайн-TTS для русского.

Управление голосом («поставь алерт…», «включи Tor») и замок по твоему голосу — следующий модуль, он в разработке. Сейчас ассистент говорит, но ещё не слушает команды.

## Голосовое управление (команды)

Раздел 🔔 → «Команды голосом». Нажми «Слушать команду» и скажи:
- «поставь алерт на продажу дороже девять миллионов семьсот тысяч»
- «включи Tor» / «выключи Tor»
- «обнови курсы»
- «открой браузер» / «открой источники» / «открой алерты»

Распознаёт и цифры, и числа словами. Работает офлайн, если в системе стоит офлайн-пакет распознавания русского; иначе может уйти в облако (полностью офлайновый ASR — это отдельный движок с моделью ~50 МБ, подключается при желании).

**Замок по голосу.** «Обучить» — 3 раза произнеси имя ассистента, он усреднит MFCC-отпечаток. Включи «Замок по голосу» — и перед каждой командой ассистент сверяет голос. Ещё раз честно: это **удобный фильтр, а не защита**. По паре фраз такой замок ошибается и обманывается записью. Секреты стережёт пароль сейфа, а не голос.

## Встроенный браузер через Tor

Иконка 🌐 в шапке. WebView, трафик завёрнут в HTTP-прокси Orbot (тот же порт 8118, та же причина — remote DNS и `.onion`). Юзер-агент как у Tor Browser, геолокация и кэш выключены, третьесторонние куки блокируются, «анонимная клавиатура» (IME не запоминает ввод). Кнопка-метёлка стирает сессию.

Это **не** настоящий Tor Browser (его фингерпринт не повторить в WebView) — для серьёзных задач используй отдельный Tor Browser. Этот нужен для быстрого анонимного захода с автозаполнением паролей из сейфа.

## Шифрованный сейф с ложным паролем

Иконка 🔒. Первый вход — задаёшь два PIN: **настоящий (5 цифр)** и **ложный (4 цифры)**.

- На экране **4 точки**. Вводишь 4 цифры и ✓ → открывается **ложный** сейф (там правдоподобная ерунда). Отдаёшь этот PIN, если заставляют.
- Вводишь **5** цифр (пятая точка не показывается — так и задумано) и ✓ → открывается **настоящий** сейф.
- По одному PIN невозможно узнать, что есть второй: у сейфов разные соли и разные блобы.

Внутри: **файлы** (шифруются AES-256-GCM, ключ из PBKDF2-HMAC-SHA256, 200 000 итераций) и **логины/пароли** для сайтов.

Честная граница: это защита данных (без PIN не прочесть) и бытовое правдоподобное отрицание. Но криминалистика файлов приложения увидит, что зашифрованных блоба **два** — «скрытого тома» уровня VeraCrypt тут нет. Для «отдал ложный пароль — отстали» хватает, для защиты от серьёзной экспертизы — нет.

## Менеджер паролей + автозаполнение

Пароли из сейфа привязаны к host. Когда в встроенном браузере открываешь сайт, для которого есть сохранённая учётка, в шапке появляется иконка 🔑 — тап подставляет логин/пароль в поля формы. Автозаполнение работает только при **открытом** сейфе.

## Что НЕ вошло и почему

Чтобы не было сюрпризов:

- **Автоматический разбор капчи — не делаю.** Капча существует ровно для отличения человека от бота; автосолвер — это обход анти-бот защиты. Единственное твёрдое «нет».
- **Парсеры под казино** отдельно не пишу и не «благословляю» — но движок источников универсальный, добавляй любой URL сам в «Источниках».
- **Скрытие иконки с рабочего стола** — Android с версии 10 это запрещает (из-за сталкерского софта). Технически невозможно. Цель «спрятать своё» закрывается скрытым разделом с ложным паролем.
- **Встроить настоящий Tor Browser** внутрь нельзя (это отдельное Firefox-приложение). Что делается: встроенный браузер на WebView через Tor/Orbot + анти-фингерпринт. Сам Tor Browser остаётся отдельным приложением, на него будет кнопка.
- **Голос «только мой»** — будет как удобный замок, но не как настоящая защита: распознавание владельца по паре фраз обманывается записью. Хранилище стережёт пароль, а не голос.

## Что показывают карточки

- **Крупная цифра** — эффективный курс, то есть **с учётом комиссии**, а не витринный. Обменник с курсом 9 500 000 и комиссией 3% честно проигрывает обменнику с 9 650 000 без комиссии, и в списке он будет ниже.
- **«получишь»** — сколько реально придёт на руки на введённую сумму. Именно по этому числу идёт сортировка, а не по курсу. Поэтому лимиты, комиссии и резерв учитываются сами собой.
- **спред** — отклонение от рыночной цены. Хуже рынка на 5% — это не «курс», это плата за что-то, и стоит понимать, за что.
- **% к топу** — насколько хуже лучшего предложения.
- Предложения, не проходящие по лимитам или резерву, уезжают вниз и гаснут, даже если курс у них красивый. Их можно вовсе спрятать галочкой.

## Трезвые оговорки

**Про цифры.** Курс на витрине и курс в момент сделки — разные вещи. Проверяй на сайте перед отправкой денег, особенно на крупных суммах. Резерв и лимиты обменники показывают неохотно и не всегда честно.

**Про Tor.** Он прячет твой IP от сайта — и всё. Анонимной саму сделку он не делает: если ты платишь со своей карты или проходишь верификацию, цепочка всё равно привязана к тебе, хоть через десять узлов заходи.

**Про .onion-обменники.** Концентрация скама там заметно выше средней, а щедрый курс часто и есть приманка. Проверяй на мелких суммах.

**Про закон.** В РФ операции с криптовалютой регулируются, и правила меняются. Налоговые и прочие последствия — на тебе; я не юрист и не налоговый консультант.
